## Shipped implementation
- `backend/app/services/standard_engine.py`: PREMIUM mode raises challenger cap from 3 to 5, Dummy is independent sixth model. One untouched holdout after random/group/chronological split; both model selection and limited tuning occur on training-CV only. Top two CV-ranked challengers (when supported) undergo 2-configuration GridSearchCV; tuned winner stored with selected params; no holdout-driven model re-selection.
- `backend/app/services/premium_delivery.py`: produce BASIC quality charts + rebranded ML comparison + 11-page Korean PDF on representative synthetic dataset + model score CSV + full model artifact + schema + runner + instructions + SHA-256 ZIP manifest. After evaluating train-only winner vs independent holdout, **final deployment pipeline refits on all labeled rows** with the selected CV hyperparameters. The original holdout score DOES NOT measure the final refit and document says so.
- `backend/app/services/premium_predict.py` is included as `predict.py` in ZIP: loads **only** `model_pipeline.skops` from locally extracted trusted bundle, verifies SHA-256, supported model format, Python minor and exact pandas/numpy/scikit-learn/skops package versions, audited default skops types plus explicitly approved `numpy.dtype` (no arbitrary trusted-list from archive). Validates exact CSV columns/order, numeric/bool types and dates. Generates one prediction per new input row to a fresh local UTF-8 CSV, never overwrites the input or an existing output file. Zip includes `predict.cmd` for Windows.
- `frontend/premium_mvp.html` / `GET /premium-mvp` / `POST /api/premium-report`: localhost-only development UI and PDF/ZIP route; legacy APIs remain risky if bound publicly.
- `requirements-premium.txt` generated in each ZIP with exact library versions; `sample_input.csv` and `sample_predictions.csv` intentionally **header-only templates**, not fabricated examples nor any customer rows. No private data or model weights committed to source repo.

## Limitations and P6 blockers
- Real **Windows-native** customer machine .cmd execution, Chrome/Edge form submission, actual ZIP extraction, Korean PDF rendering on Windows, fonts and license compliance remain UNVERIFIED.
- `skops.io` is a safer alternative to pickle but trusted source is still required. SHA-256 detects accidental changes only; it does NOT authenticate issuer or prevent a rehashed malicious archive. Consumer must only open known first-party produced bundles.
- Pipeline preprocessing feature definitions are chosen on train subset, but some unsupervised feature dropping is not inside every CV fold; CV scores may be optimistic especially after tuning. Correlated target-derived variable leakage is not fully automated; grouped/ordered split is only as correct as supplied metadata.
- Schema requires exact raw input columns/order and Python/dependency versions; portability across heterogeneous Windows installations is untested. Only CSV input currently supported; XLSX ingestion is still missing from promised SKU matrix.
- Performance, DoS, non-UTF CSV traps, model weight size, high-cardinality data, accuracy/class imbalance, real-customer privacy controls, local file access APIs, permissive legacy CORS and filesystem exposure need final QA. **No public deployment or sales until P6 passes**.
