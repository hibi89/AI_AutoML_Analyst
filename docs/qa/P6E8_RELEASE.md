## Evidence-driven pivot after two Windows failures (2026-10-27 KST)
- The first Windows attempt failed to locate an absolute `cmd.exe /c` batch path containing Korean characters. The second attempt changed only to `cmd.exe /c predict.cmd` in its working directory and reached Python, then exposed **UnicodeEncodeError: 'charmap' codec can't encode Korean path characters** while printing to a legacy Windows console stream. [Second failed run 40457917488](https://github.com/hibi89/AI_AutoML_Analyst/actions/runs/40457917488) showed **66 pass /1 fail**, not a successful release.
- Instead of retrying more quoting guesses, pivoted to repairing the real CLI output: `premium_predict.main()` configures stdout/stderr encoding errors as `backslashreplace` while leaving written prediction CSV UTF-8. Commit [e79199e](https://github.com/hibi89/AI_AutoML_Analyst/commit/e79199e5642994c845176d1fcf224aef37bf9138). This avoids post-write exit failure on machines whose console cannot represent a Korean destination path. Verification **pending**, not assumed.
- The synthetic owner preflight `scripts/p6e5_windows_demo.py` now invokes `predict.cmd` from `cwd=trusted` instead of embedding a Unicode absolute path in `cmd.exe /c`, matching the documented relative invocation. Commit [45c6272](https://github.com/hibi89/AI_AutoML_Analyst/commit/45c6272b2007cc41130ae6cf85ba48998146de6a). This is a different execution path from the failing absolute-path harness, not evidence of owner's physical Windows PASS.
